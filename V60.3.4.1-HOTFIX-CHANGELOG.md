# TeoStudio V60.3.4.1 – Runtime hotfix

## Root cause found
Several HTML pages referenced JavaScript assets with `&patch=604` directly in the path instead of starting a query string with `?patch=604`. Browsers therefore requested literal paths such as `/assets/js/main-v604.js&patch=604`, which do not exist.

On the new main homepage this prevented `main-v604.js` from executing. That script is responsible for loading `/api/products`, `/api/tags`, and `/api/settings`, rendering products/tags, and updating the counters. This explains why the new homepage showed 0 items while `/2` (which loads `main.js`) could still show products.

## Changes
- Corrected malformed JavaScript asset query strings from `.js&patch=604` to `.js?patch=604` in all affected HTML pages.
- Affected pages: `frontend/index.html`, `frontend/detail.html`, `frontend/tenant-admin.html`, `frontend/tenant-detail.html`, and root `index.html` where applicable.
- No Worker routes, D1 schema, product data, secrets, or payment configuration were changed.

## Deployment note
Upload/deploy this ZIP using the same deployment method as the currently active V60.3.4 package. After deploy, hard-refresh the homepage or clear its cached assets. Check that `/assets/js/main-v604.js?patch=604` returns JavaScript (HTTP 200), then verify `/api/products` and `/api/tags` return populated arrays.
